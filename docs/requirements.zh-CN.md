# 需求与验收判据

[English](requirements.md) | **中文** | [Español](requirements.es.md)

> 本文档是 Wispkit 的需求契约：每项已交付能力都有稳定的需求编号、可判定的验收判据，以及所有其余文档必须遵守的变更协议。

## 本文档的地位

Wispkit 是 Visual Studio Code 的浏览增强扩展。本文档陈述**扩展应当做什么**，与该行为的实现方式无关。

- **本文档是需求的权威陈述。** 任何其他文档与本文档冲突时，以本文档为准，另一份文档即为缺陷。
- [架构](architecture.zh-CN.md)、[视图与交互](views-and-interaction.zh-CN.md)、[配置参考](configuration.zh-CN.md)、[构建与验证](build-and-verify.zh-CN.md) 属于**实现说明**：它们描述一项能力如何实现、一个数字如何复现，既不扩大也不缩小本文档承诺的范围。
- **未列入本文档的行为不构成承诺。** 一个存在但没有需求编号的行为属于实现细节，可以随时改变。
- **每一处已知失败与每一项未验证内容，在[已知限制](limitations.zh-CN.md)里有一个位置，在[§6 缓期与排除](#6-缓期与排除)里有一行对应。** 两者不得互相矛盾；出现矛盾即为文档缺陷，不是措辞差异。

## 阅读约定

### 规范性用词

| 用词 | 含义 |
|---|---|
| **SHALL** / **MUST**（应当 / 必须） | 绝对要求。违反它的版本即为缺陷，不存在「大致正确」。 |
| **SHALL NOT** / **MUST NOT**（不得 / 禁止） | 绝对禁止。 |
| **MAY**（可以） | 真正可选，两种选择都符合规范。 |
| **WHEN … THEN …** | 每条验收判据的强制句式：触发情境，然后是外部可观察的结果。 |

### 需求与判据的编号

| 标识 | 含义 |
|---|---|
| `R<n>` | 一条需求。编号**按能力被立项的先后顺序**分配，永不复用。 |
| `AC-R<n>.<m>` | 需求 *n* 的第 *m* 条验收判据。没有判据的需求不构成需求。 |
| `demo/R<n>-*/` | 需求 *n* 的验收素材集。这层对应关系是契约的一部分：重命名或删除素材目录即破坏可追溯性。 |

三条编号事实是承重的，任何后续修改都必须保住：

1. **`R7` 已退役，不得复用。** 它最初同时分配给一同立项的两项能力 —— 全局只读模式与资源管理器子树面板 —— 二者后来被拆开。两项能力各自获得了编号（`R10` 与 `R11`），共用的编号被**腾空**而不是重新指派，以免历史引用悄悄改变含义。
2. **`R12` 不是一项独立能力。** 它是 XAML 视图的渲染器被替换之后重新生产的素材集，记录在 `R6` 之下。`demo/R6-xaml/` 与 `demo/R12-xaml/` 都是 `R6` 的合法验收素材；不得以「另一份已经覆盖」为由删除其中任何一份。
3. **`R9` 覆盖的是一个视图，不只是素材目录。** 它的实际存储文件在首次编辑时才创建，因此新工作区在加载 `demo/R9-resource-tree/` 之前显示空树是正常状态。

## 1. 产品意图

1. **扩展应当在不修改宿主的前提下增强浏览。** 它不得给 Visual Studio Code 的安装目录打补丁、替换或写入，也不得携带任何被修改过的内置扩展资源。每项能力都通过公开的扩展面交付，宿主升级后无需重新打补丁即可继续工作。
2. **宿主应当掌握路径，前端应当掌握交互。** 前端里的资源 URL 必须被当作不透明标识，不得反解为文件系统路径。当前端需要真实路径或源码片段时，它应当上报一个位置，由宿主重新从原文中读取路径。
3. **渲染应当经过宿主自己的管线。** Markdown 应当由宿主内置的 Markdown 渲染器渲染，使其他扩展贡献的每一个第三方插件继续生效。扩展不得在默认路径上替换为私有的 Markdown 实现。
4. **「只读」应当意味着「没有加载」，而不是「禁止编辑」。** 只读模式的目的正是省掉加载成本，因此它必须避免把整份文档实体化；限制加载窗口是需求本身，不是优化。
5. **一项能力只能根据外部可观察的结果来判定。** 验收判据应当描述用户或自动观察者在某次操作之后能看到什么，而不是描述某条规则、某个设置或某条消息存在。

## 2. 范围与非目标

### 范围内

| 领域 | 由哪些需求交付 |
|---|---|
| Markdown 浏览：目录导航、正文缩放、文档内查找、媒体右键菜单、drawio 就地编辑、段落原地编辑、大文档性能 | `R1`、`R2`、`R15`、`R16`、`R17` |
| 图表浏览：Markdown 里的 Mermaid 放大、独立 Mermaid 文件视图、3D 拓扑浏览 | `R3`、`R8`、`R13` |
| 媒体浏览：图片滚轮缩放与按键拖动平移、视频播放与系统播放器兜底 | `R4`、`R14` |
| 网页内容：HTML 视图与内部链接路由 | `R5` |
| XAML 源码与渲染并排 | `R6` |
| 只读文本浏览与解锁路径 | `R10` |
| 文件组织：活动栏自定义资源树、资源管理器子树面板 | `R9`、`R11` |
| 扩展自身界面的本地化 | `R18` |

### 范围外

| 不做的事 | 理由 |
|---|---|
| 接管宿主的 Simple Browser 页面 | 它由命令创建为 webview 面板，从不进入自定义编辑器竞争；公开扩展面无法表达「接管一个已存在的面板」 |
| 改变任何内置扩展的行为或资源 | 违反意图 1；内置扩展只会被*消费*，不会被修改 |
| 编辑器与预览之间的滚动同步 | 需要预览并不产出的源映射协议；目录导航刻意不依赖它 |
| 渲染输出与源码行之间的通用源映射层 | 唯一被消费的源码行是定位段落所需要的那一行；完整的行映射是另一项能力，有其自身的精度预算 |
| 为图片与视频打包大型第三方解码器 | 诸如 HEIF 这类编解码器要花掉数兆字节，与「不引入大依赖」的规则冲突；这些格式得到的是明确交接，不是内置解码 |
| 为 3D 场景提供 2D 降级 | 3D 面板是拓扑仪器而不是图表渲染器；二维投影会悄悄承诺另一个产品 |
| 为视觉一致性重新实现图表库的渲染器 | 3D 只消费拓扑；与图表库主题的像素级一致已被明确排除在承诺之外 |
| 渲染 XAML 时预加载跨文件资源字典 | 需要解析整个应用的资源图，这既与应用相关又无边界 |

## 3. 需求

### R1  第三方 Markdown 预览脚本在严格 CSP 下运行

**需求。** Markdown 视图应当执行其他已安装扩展通过宿主 Markdown 预览贡献点贡献的每一个脚本、应用其每一份样式表。视图必须使用严格的内容安全策略：脚本只能凭 nonce 获准，且不得通过放宽策略来允许内联脚本。文档发生变化时，扩展应当通知被贡献的脚本以便重新渲染。

**理由。** Markdown 生态中的图表渲染、公式排版与语法着色都以被贡献的预览脚本形式到达。私有渲染器会静默丢弃它们，这正是意图 3 把宿主管线定为强制项的原因。复用宿主自己的策略意味着：一份按内置预览编写的第三方脚本，在这里无需改动即可工作。

**验收判据。**

- **AC-R1.1** — **当**某个已安装扩展贡献了预览脚本或样式，**则**打开一份 Markdown 文档后能看到它的渲染产物（图表、公式、高亮），无需针对该扩展做任何配置。
- **AC-R1.2** — **当**视图完成渲染，**则**内容安全策略违规计数为零。
- **AC-R1.3** — **当**文档文本发生变化，**则**被贡献的脚本重新执行，其产物反映新的文本。
- **AC-R1.4** — **当**贡献该脚本的扩展被卸载后重新打开文档，**则**视图仍然渲染，且不报错。
- **AC-R1.5** — **当**文档里存在相对图片引用，**则**它从文档自身所在目录加载，而不是从扩展安装目录加载。

**证据。** [视图与交互 → Markdown 视图](views-and-interaction.zh-CN.md#markdown-视图wispkitmarkdown)；素材在 `demo/R1-injection/`；实测见[构建与验证](build-and-verify.zh-CN.md)。

### R2  目录导航跟随文档

**需求。** Markdown 视图应当提供一个列出文档全部标题的侧栏，应当在正文滚动时高亮当前所在小节，并应当在某个条目被激活时跳转到对应标题。侧栏宽度应当可调且可复位，侧栏应当能一键移除。

**理由。** 长文档是靠结构导航的。高亮由渲染后的几何位置推导，而不是来自源映射，这正是让本能力独立于滚动同步的原因。

**验收判据。**

- **AC-R2.1** — **当**打开一份含标题的文档，**则**侧栏条目数等于文档实际包含的标题数。
- **AC-R2.2** — **当**正文滚动到某个小节，**则**该小节条目显示为当前项，且没有条目停留在过期状态。
- **AC-R2.3** — **当**某个条目被激活，**则**对应标题落在视口顶部，误差不超过一个行高。
- **AC-R2.4** — **当**分隔条被拖动后再被双击，**则**侧栏恢复到默认宽度。
- **AC-R2.5** — **当**侧栏被配置禁用，**则**整个侧栏不存在，正文占据全部宽度。
- **AC-R2.6** — **当**文档被编辑导致标题增删，**则**侧栏重建后仍满足 AC-R2.1。

**证据。** [视图与交互 → 目录](views-and-interaction.zh-CN.md#目录导航)；素材在 `demo/R2-toc/`。

### R3  Markdown 里的 Mermaid 图默认可缩放平移

**需求。** Markdown 视图应当让读者**无需按住修饰键**就能放大和平移一张 Mermaid 图，并应当提供全窗口视图以便细看。文档被编辑、图表重新渲染之后，放大能力应当仍然可用。

**理由。** 放在文档栏宽里的图经常在布局尺寸下无法辨认，而要求修饰键会让这项能力事实上无人发现。能力属于文档的读者，而读者可能根本没有配置任何图表扩展。

**验收判据。**

- **AC-R3.1** — **当**图表已显示且指针位于其上，**则**滚轮改变其缩放比例，且无需按住任何修饰键。
- **AC-R3.2** — **当**图表已被放大，**则**拖动可以平移，复位手势可使其回到原始比例。
- **AC-R3.3** — **当**文档被编辑、图表重新渲染后，**则**新的产物上放大与平移仍然有效。
- **AC-R3.4** — **当**放大视图打开，**则**关闭后文档恢复原状，文档中的图表未被改动。
- **AC-R3.5** — **当**在全窗口视图里放大图表，**则**其配色与它在文档栏中时一致。

**证据。** [视图与交互 → 媒体右键菜单](views-and-interaction.zh-CN.md#媒体右键菜单)；素材在 `demo/R3-mermaid/`；取消修饰键要求的配置默认值记录在[配置参考](configuration.zh-CN.md)。

### R4  图片滚轮缩放与按键拖动平移

**需求。** 图片视图应当以普通滚轮手势缩放并以指针为锚点，应当在拖动按键被按住时平移，应当在双击时在适应窗口与 100% 之间切换。放大幅度超过位图源分辨率后不应当糊成一片；矢量图应当按新布局尺寸重新渲染。对于宿主运行时无法解码的格式，视图应当说明原因并提供交接方式，而不是显示空白页。

**理由。** 浏览图片是比对任务：读者想看清细节又不愿丢失位置。以指针为锚点，正是让连续滚轮手势收敛到关注点而不是逐渐漂移的原因。

**验收判据。**

- **AC-R4.1** — **当**指针位于图片上且滚轮转动、无需修饰键，**则**图片围绕指针缩放，视图中心不跳动。
- **AC-R4.2** — **当**配置的拖动按键被按住且指针移动，**则**图片平移；松开按键则停止平移。
- **AC-R4.3** — **当**图片被双击，**则**它在适应窗口与 100% 之间切换。
- **AC-R4.4** — **当**位图被放大到超过适应尺寸的三倍，**则**它以最近邻方式渲染，使像素保持可辨认。
- **AC-R4.5** — **当**矢量图被放大，**则**它的布局尺寸发生变化而不只是变换矩阵变化，从而边缘保持锐利。
- **AC-R4.6** — **当**打开一个属于已支持但无法解码格式的文件，**则**页面说明原因，并同时提供交给系统默认应用和复制路径两个动作。
- **AC-R4.7** — **当**缩放配置被关闭，**则**滚轮不再缩放，恢复到需要修饰键的行为。

**证据。** [视图与交互 → 图片视图](views-and-interaction.zh-CN.md#图片视图wispkitimage)；素材在 `demo/R4-image/`；探针结果见[构建与验证](build-and-verify.zh-CN.md)。

### R5  渲染内容里的链接在宿主窗口内打开

**需求。** Markdown 视图与 HTML 视图都应当路由链接的激活：相对目标应当相对文档自身目录解析；指向编辑器内文件并带行号的目标应当**在当前窗口**打开并定位到该行；文档内锚点应当滚动文档；宿主自己能处理的目标（网页、邮件、已支持的其他协议）应当交给宿主处理。页面自身已经阻止了默认激活的链接，不得被扩展重新打开。

**理由。** 文档经常按路径与行号互相引用源文件。把这类链接抛给系统浏览器会丢失位置并打断阅读上下文。

**验收判据。**

- **AC-R5.1** — **当**相对链接被激活，**则**目标相对文档所在目录解析并打开，而不是相对扩展安装目录。
- **AC-R5.2** — **当**一个带行号的文件链接被激活，**则**该文件在当前窗口打开且光标位于该行 —— 不新开窗口，也不交给系统浏览器。
- **AC-R5.3** — **当**文档内锚点被激活，**则**文档滚动到该处，不发生页面重载。
- **AC-R5.4** — **当**网页或邮件链接被激活，**则**由宿主按其自身策略处理。
- **AC-R5.5** — **当**页面自身阻止了某条链接的默认激活，**则**扩展不再重新打开它。
- **AC-R5.6** — **当**页面自带脚本被其内容安全策略阻止，**则**两种被改写的链接形式仍然可以导航。

**证据。** [视图与交互 → HTML 视图](views-and-interaction.zh-CN.md#html-视图wispkithtml)；素材在 `demo/R5-jump/`。

### R6  XAML 源码与渲染结果并排

**需求。** XAML 视图应当在 `.xaml` 文件的源码旁显示它的渲染图，应当允许编辑源码并用当前文本立即重新渲染而不必先存盘，应当允许渲染图缩放、平移与全窗口查看。保存应当写回同一个文件。渲染结果应当被呈现为静态快照；渲染失败时视图应当说明原因。

**理由。** 只看布局定义而看不到结果等于猜；为了看效果而反复切窗口则很慢。本能力刻意是快照：对着实时数据求值并运行事件处理器需要把应用托管起来，这违反意图 1。

**验收判据。**

- **AC-R6.1** — **当**一个 `.xaml` 文件在本视图中打开，**则**源码与它的渲染图并排显示。
- **AC-R6.2** — **当**源码被编辑并请求重新渲染，**则**新图反映编辑后的文本，且此时文件尚未保存。
- **AC-R6.3** — **当**源码被保存，**则**磁盘上的文件与编辑后的文本一致。
- **AC-R6.4** — **当**渲染图显示时，**则**滚轮可缩放、按住按键拖动可平移、可使用全窗口视图。
- **AC-R6.5** — **当**渲染失败，**则**页面说明失败及常见原因，而不是显示一片空白。
- **AC-R6.6** — **当**同一份 `.xaml` 在文本不变的情况下渲染两次，**则**两次结果都非空白且视觉等价。
- **AC-R6.7** — **当**根元素是一个在快照中无法实例化的类型，**则**视图仍通过在其基类型上承载来渲染出布局，或者说明为什么无法渲染。

**证据。** 素材在 `demo/R6-xaml/`（第一代）与 `demo/R12-xaml/`（第二代，附带渲染产物记录）；渲染器契约与实测覆盖率见[渲染器说明](../tools/xaml-render/README.md)；快照边界见[已知限制](limitations.zh-CN.md#6-xaml-渲染是静态快照)。

### R8  Markdown 与 Mermaid 图的 3D 拓扑浏览

**需求。** 扩展应当打开一个 3D 面板，渲染 Markdown 文档或 Mermaid 文件里图表元素的拓扑；应当允许两个元素并排显示并通过同名节点合并；应当提供相机、布局与间隔控制。面板应当说明是否发生了合并、合并了多少个节点，以及哪些流向终止于占位符。

**理由。** 积累多版图表的文档是按结构比对的：哪些节点共享、哪些独有。并排读两张 2D 图等于用眼睛做 diff。

**验收判据。**

- **AC-R8.1** — **当**在 Markdown 文件上调用 3D 入口，**则**面板打开并列出该文档里的每个图表元素，名称由文档内容派生而不是由文件偏移派生。
- **AC-R8.2** — **当**面板已打开时再次请求同一个文件，**则**现有面板被显示，不创建第二个面板。
- **AC-R8.3** — **当**选中两个元素，**则**它们并排显示，中间有一条受限范围可拖动的分隔条，双击可复位。
- **AC-R8.4** — **当**请求合并，**则**两侧同名节点合并为一个，重复的流被折叠，面板说明合并了多少个。
- **AC-R8.5** — **当**两个元素没有任何同名节点，**则**合并仍然成功，报告合并零个，两侧在视觉上保持可区分。
- **AC-R8.6** — **当**指针按住主按键拖动，**则**相机旋转；按住次按键拖动则平移；滚轮缩放。
- **AC-R8.7** — **当**某个节点的标签是标记「对侧不存在」的占位符，**则**它不被画成气泡，与它相连的流变成悬空边且箭头方向保持不变。
- **AC-R8.8** — **当**文档超过所声明的元素或节点上限，**则**超出部分被截断，且截断被报告而不是静默执行。
- **AC-R8.9** — **当**运行时无法提供 3D 上下文，**则**面板说明失败，而不是降级为 2D 渲染。

**证据。** [视图与交互 → 3D 可视化浏览](views-and-interaction.zh-CN.md#3d-可视化浏览wispkitgraph3d)；素材在 `demo/R8-graph3d/`；探针结果见[构建与验证](build-and-verify.zh-CN.md)。

### R9  活动栏里的自定义资源管理

**需求。** 扩展应当提供一个活动栏视图，让用户把常用文件夹组织成一棵由虚拟组与文件夹组成、层级任意的树。这棵树应当持久化为工作区内的 JSON 文档，应当既能通过视图编辑也能作为文件编辑，每一次改动都应当立即且原子地写入。重命名、移动与删除只应当作用于这棵树，从不作用于文件系统。

**理由。** 常用文件夹散落在工作区各处，每次访问都要付出一段点击路径。把它们组织起来是对工作区的标注，不是文件系统操作，因此这棵树绝不能作为副作用移动文件。

**验收判据。**

- **AC-R9.1** — **当**没有打开任何工作区文件夹，**则**视图说明需要工作区，并指明这棵树本应存放的位置。
- **AC-R9.2** — **当**树为空，**则**视图提供创建内容的动作，并说明不会移动或删除任何文件。
- **AC-R9.3** — **当**节点被新增、重命名、移动或删除，**则**存储文档立即反映新的结构，且磁盘上没有任何文件或目录被重命名、移动或删除。
- **AC-R9.4** — **当**文件夹节点存储的路径无法解析，**则**该节点显示具体的警告状态，区分不存在、不是文件夹与占位符无法解析三种情况，树的其余部分仍可使用。
- **AC-R9.5** — **当**一次移动会把节点放进它自己的后代之中，**则**移动被拒绝并给出说明。
- **AC-R9.6** — **当**存储文档被外部编辑后请求刷新，**则**树重新加载；**当**文档不合法时，**则**保留当前树且不覆盖该文件。
- **AC-R9.7** — **当**一次写入被中断，**则**此前存储的文档仍然完整。
- **AC-R9.8** — **当**树超过所声明的节点、子节点或深度上限，**则**超出部分在加载时被截断且截断被报告。
- **AC-R9.9** — **当**虚拟组被激活，**则**视图解释虚拟组没有磁盘对应物，而不是什么都不做。

**证据。** [视图与交互 → 自定义资源管理](views-and-interaction.zh-CN.md#自定义资源管理wispkitresourcetree)；素材在 `demo/R9-resource-tree/`；探针结果见[构建与验证](build-and-verify.zh-CN.md)。

### R10  不加载文档的全局只读模式

**需求。** 扩展应当提供一个状态栏控件，把编辑器切换到全局只读模式。在该模式下，属于已配置类型的文本文件应当显示为只读预览，只加载该文件一个有界的窗口；应当提供一个明确的动作把该文件改回可编辑的编辑器打开；应当在所显示内容被截断时说明这一点。该模式不应当作用于扩展自身拥有的浏览视图。

**理由。** 打开一个大文件只为看开头，不应当付出加载整份文件的内存代价，也不应当冒误改的风险。两个目标都要求文档不被实体化，这正是「内容会被截断」成为需求而不是缺陷的原因。

**验收判据。**

- **AC-R10.1** — **当**只读控件被打开并打开一个已配置类型的文件，**则**它以只读预览打开，而不是在文本编辑器中打开。
- **AC-R10.2** — **当**在该模式下打开一个大于所配置字节上限的文件，**则**预览说明只加载了开头一部分，以及文件总共有多大。
- **AC-R10.3** — **当**达到所配置的行数上限，**则**预览停在该行并说明这一点，其余部分不显示。
- **AC-R10.4** — **当**使用解锁动作，**则**该文件在可编辑的编辑器中打开，且它的只读预览被关闭。
- **AC-R10.5** — **当**模式被关闭，**则**此后打开的文件回到其常规编辑器。
- **AC-R10.6** — **当**在只读模式下打开一个属于扩展自身浏览视图的文件类型，**则**它照常在该浏览视图中打开，不被截断。
- **AC-R10.7** — **当**应用启动且模式被配置为默认开启，**则**控件反映已激活状态，无需用户切换。

**证据。** [视图与交互 → 只读文本视图](views-and-interaction.zh-CN.md#只读文本视图wispkittext)；素材在 `demo/R10-readonly/`；探针见[构建与验证](build-and-verify.zh-CN.md)。

### R11  资源管理器子树面板与文件夹入口

**需求。** 扩展应当在资源管理器的文件夹行上提供一个入口，为该文件夹打开子树面板；并提供第二个入口，打开该文件夹所声明的展示入口。子树面板应当显示可配置的列，应当只在某一层被展开时才读取该层，应当对选中项提供文件操作与用户自定义工具，并应当接受双向拖放。对同一文件夹重复发起同一请求，应当复用已存在的面板。

**理由。** 资源管理器只呈现一列名称，要查看大小、时间或类型就得离开它。跟随选择出现的临时面板保住了浏览上下文而不是与之竞争，这正是它被做成面板而非又一个常驻视图的原因。

**验收判据。**

- **AC-R11.1** — **当**查看一个文件夹行，**则**两个入口都被提供，且在非文件夹行上不出现。
- **AC-R11.2** — **当**同一文件夹的面板被请求两次，**则**已存在的面板被显示，而不是重复创建。
- **AC-R11.3** — **当**某一层被折叠后再次展开，**则**该层在展开时才被读取。
- **AC-R11.4** — **当**列配置被修改，**则**面板按配置的顺序显示配置的列，非法项被忽略而不是导致失败。
- **AC-R11.5** — **当**某一列的底层值不被宿主暴露，**则**该列显示明确的占位符，而不是编造一个值。
- **AC-R11.6** — **当**用户自定义工具被执行，**则**其声明的占位符被替换，并在声明的执行模式下运行；未知占位符应当原样保留，而不是被静默清空。
- **AC-R11.7** — **当**操作区提供的某个宿主命令不可用，**则**警告指出缺失的命令，而不是静默失败。
- **AC-R11.8** — **当**文件从操作系统拖入、或在两个子树面板之间拖动，**则**相应文件操作被执行且结果被报告。
- **AC-R11.9** — **当**某目录包含的条目超过所声明的上限，**则**超出部分被截断，且面板中说明了截断。

**证据。** [视图与交互 → 子树面板](views-and-interaction.zh-CN.md#子树面板wispkitsubtree)；素材在 `demo/R11-subtree/`；探针结果见[构建与验证](build-and-verify.zh-CN.md)。

### R13  独立 Mermaid 文件视图

**需求。** 独立的 Mermaid 文件应当在一个视图中打开并渲染其图表，并应当提供「源码」「刷新」与「进入 3D 浏览」三个入口。当宿主不提供 Mermaid 渲染脚本时，视图应当降级为显示源码并给出说明，而不是显示空白页。

**理由。** 图表源文件本来只是文本。复用宿主的 Mermaid 脚本让整个产品只保留一种渲染行为，而不是两种会彼此漂移的行为。

**验收判据。**

- **AC-R13.1** — **当**一个 Mermaid 文件在此视图中打开，**则**其图表被渲染，状态行报告图表种类及节点数与边数。
- **AC-R13.2** — **当**使用「源码」入口，**则**同一文件在视图旁的普通文本编辑器中打开。
- **AC-R13.3** — **当**文件变化后使用刷新，**则**图表反映新的源码。
- **AC-R13.4** — **当**使用「3D」入口，**则**为本次文件打开 3D 面板，并报告相同的元素计数。
- **AC-R13.5** — **当**没有可用的 Mermaid 渲染脚本，**则**视图显示源码并给出说明，同时工具栏动作仍然可用。

**证据。** [视图与交互 → Mermaid 文件视图](views-and-interaction.zh-CN.md#mermaid-文件视图wispkitmermaid)；素材为 `demo/R8-graph3d/04-standalone.mmd`；实测见[构建与验证](build-and-verify.zh-CN.md)。

### R14  编辑器内的视频播放

**需求。** 常见的视频容器应当在一个使用宿主自身媒体元素的视图中打开，不打包播放器。视图应当提供交给系统播放器的交接方式与复制路径动作，应当对无法播放的格式说明原因而不是显示静默的黑块，并应当在离开视图时停止播放。

**理由。** 看一段视频不应该要求离开编辑器。播放能力属于运行时；承诺超出运行时解码范围的能力就是产品无法兑现的承诺，这正是把兜底纳入需求的原因。

**验收判据。**

- **AC-R14.1** — **当**一个受支持的视频文件在此视图中打开，**则**它以运行时的原生控件播放，并在已知时报告时长。
- **AC-R14.2** — **当**运行时无法播放该文件的编码或容器，**则**页面说明原因并提供交给系统播放器的交接，而不是一片空白画面。
- **AC-R14.3** — **当**使用复制路径动作，**则**绝对路径到达剪贴板。
- **AC-R14.4** — **当**用户切换到另一个标签页，**则**播放停止。
- **AC-R14.5** — **当**某个扩展名同时是某种编程语言的源码扩展名，**则**它不被视频视图占用。

**证据。** [视图与交互 → 视频视图](views-and-interaction.zh-CN.md#视频视图wispkitvideo)；探针结果见[构建与验证](build-and-verify.zh-CN.md)。

### R15  Markdown 视图里的段落原地编辑

**需求。** Markdown 视图应当提供编辑模式：激活一个已渲染的段落时，把**该段落**就地变成编辑框，文档其余部分保持渲染。编辑框应当原样承载该段落的源码，应当把段落分隔与软换行表达为不同操作，应当支持提交与丢弃当前段落，并应当通过宿主的常规编辑路径保存，使改动可撤销。

**理由。** 分栏编辑器迫使读者在两个视图之间建立对应关系；在阅读位置编辑段落让文档本身成为注意对象。把范围限制在一个段落，正是让该模式足够便宜、可以作为开关而不是第二个编辑器保留的原因。

**验收判据。**

- **AC-R15.1** — **当**编辑模式开启且某个段落被激活，**则**该段落变成可编辑框并原样承载其源码，其他段落保持渲染。
- **AC-R15.2** — **当**在编辑框内输入换行，**则**产生段落分隔；**当**输入带修饰键的换行，**则**产生不分割段落的软换行。
- **AC-R15.3** — **当**当前段落被提交，**则**改动被写入文档并立即保存。
- **AC-R15.4** — **当**使用丢弃动作，**则**该段落的改动被放弃，渲染形态被恢复。
- **AC-R15.5** — **当**在段落正在编辑时保存文档，**则**尚未提交的文本先被提交。
- **AC-R15.6** — **当**一次编辑被提交，**则**该改动可通过宿主的常规撤销恢复。
- **AC-R15.7** — **当**编辑模式关闭，**则**不会为编辑目的加载源码文本。

**证据。** [视图与交互 → 编辑模式](views-and-interaction.zh-CN.md#编辑模式光标段落就地编辑)；行推断的边界见[已知限制](limitations.zh-CN.md#8-编辑模式没有语法高亮)。

### R16  Markdown 视图里的文档内查找

**需求。** Markdown 视图应当提供查找栏：高亮正文中的全部匹配、报告当前匹配位置与总数、双向跳转、支持区分大小写，并在关闭时清除高亮。当正文中有文本被选中时，打开查找栏应当用该文本预填查询。搜索不应当进入图表、绘图或矢量图形区域。

**理由。** 在长篇已渲染文档里查一个词，读者需要一次看到全部出现位置，而不是一次一个；进入图表区域会产生读者无法处理的匹配，以及第三方渲染器可以使之失效的范围。

**验收判据。**

- **AC-R16.1** — **当**输入查询，**则**正文中每一处匹配被高亮，并显示匹配总数。
- **AC-R16.2** — **当**使用下一个或上一个动作，**则**当前匹配前进或后退，并报告其位置。
- **AC-R16.3** — **当**切换区分大小写，**则**匹配集合相应重算。
- **AC-R16.4** — **当**查找栏被关闭，**则**全部高亮被移除，文档其他方面不变。
- **AC-R16.5** — **当**正文有选中文本时打开查找栏，**则**查询被该文本预填。
- **AC-R16.6** — **当**查询命中图表或矢量图形内部的内容，**则**它不被报告为正文匹配。
- **AC-R16.7** — **当**匹配被高亮，**则**文档自身内容不为了标记而重写。

**证据。** [视图与交互 → 正文缩放与查找](views-and-interaction.zh-CN.md#正文缩放与查找)；实测见[构建与验证](build-and-verify.zh-CN.md)与 [README 实测表](../README.zh-CN.md#实测过的行为)。

### R17  Markdown 视图的正文缩放

**需求。** Markdown 视图应当通过工具栏控件与键盘手势提供足够细致的正文缩放，缩放只应当作用于文档正文，应当保持工具栏与目录侧栏为自身尺寸，并应当按文档记住缩放档位。

**理由。** 渲染后的内容要按读者合适的尺寸阅读；缩放整个窗口会让读者需要保持不变的控件一起变大。

**验收判据。**

- **AC-R17.1** — **当**使用工具栏缩放控件，**则**正文比例在所声明的最小值与最大值之间按固定档位变化。
- **AC-R17.2** — **当**使用复位手势，**则**正文回到默认比例。
- **AC-R17.3** — **当**正文被缩放，**则**工具栏与目录侧栏保持自身尺寸。
- **AC-R17.4** — **当**文档被关闭后重新打开，**则**它上次的缩放档位被恢复。
- **AC-R17.5** — **当**正文被缩放，**则**其中的图表与绘图不被二次缩放。

**证据。** [视图与交互 → 正文缩放与查找](views-and-interaction.zh-CN.md#正文缩放与查找)；配置值见[配置参考](configuration.zh-CN.md)。

### R18  扩展自身界面被本地化

**需求。** 扩展自身拥有的每一条用户可见字符串 —— 命令标题、视图名称、设置描述 —— 都应当通过宿主的本地化机制提供，且扩展应当至少携带与其文档相同的语言集合。没有译文的字符串应当回退到默认语言，而不是显示一个键名。

**理由。** 扩展自己的命令与设置出现在宿主的命令面板与设置页里，紧邻完全本地化的内置功能。在那里只提供一种语言，无论视图本身表现多好，都会让产品显得未完成。

**验收判据。**

- **AC-R18.1** — **当**宿主以扩展所携带的某种界面语言运行，**则**其命令标题、视图名称与设置描述以该语言出现。
- **AC-R18.2** — **当**宿主以扩展未携带的语言运行，**则**出现默认语言字符串，且不显示未翻译的键名。
- **AC-R18.3** — **当**新增一个命令、视图或设置，**则**它在同一次改动中被加入每一份已携带的语言包。

**证据。** [配置参考](configuration.zh-CN.md)；测量缺口见[已知限制](limitations.zh-CN.md)的未验证项 5。

## 4. 横切约束

以下约束适用于上述每一条需求，不在每条需求下重复。

### C1  内容安全

- **C1.1** — 渲染 Markdown 或 XAML 的视图应当使用严格策略：脚本只能凭 nonce，资源只能来自视图自身的源，不得通过放宽策略允许内联脚本。
- **C1.2** — 渲染任意 HTML 的视图**可以**使用放宽策略，因为页面自带脚本就是内容本身。这种放宽应当在[安全边界](../README.zh-CN.md#安全边界)与[已知限制](limitations.zh-CN.md#3-html-视图使用宽松-csp)中记录。
- **C1.3** — 视图被允许作为资源读取的每一个文件都应当被声明；只要文档可以引用同目录资源，该声明就应当包含文档自身目录。
- **C1.4** — 写入磁盘的动作只能写入用户明确选择的目标，或用户正在编辑的那个文件。

### C2  宿主与前端边界

- **C2.1** — 前端里的资源 URL 应当被视为不透明。前端不得试图从中推导文件系统路径。
- **C2.2** — 当前端需要标识某个资源时，它应当上报一个位置（序号加类型），由宿主重新读取原文档。
- **C2.3** — 两侧之间的每条消息都应当是有名字、且载荷被声明的消息；无名或随手定义的载荷不符合规范。
- **C2.4** — 两侧共享的逻辑不得依赖宿主 API，以便它仍能在不启动编辑器的情况下被测试。

### C3  只读语义

- **C3.1** — 只读模式应当同时以字节上限与行数上限限制加载窗口，并把截断情况告知读者。
- **C3.2** — 只读模式不得作用于扩展自身的浏览视图；截断一份要被渲染的文档只会产出残缺的渲染结果，而不是更小的结果。
- **C3.3** — 以只读形式呈现的文件应当有一条明确的路径回到可编辑编辑器；没有出口的模式会变成陷阱。

### C4  性能与规模

| 限制 | 数值 | 适用处 |
|---|---|---|
| 每篇文档的图表元素 | 200 | 3D 浏览 |
| 每张图的节点数 | 600 | 3D 浏览 |
| 资源树节点 / 每层子节点 / 深度 | 2000 / 200 / 12 | `R9` |
| 每层显示的条目数 | 2000 | `R11` |
| 只读加载窗口 | 默认 65536 字节 / 800 行，两者均可配置 | `R10` |
| 正文虚拟化阈值 | 约 4000 个元素，或 40 个表格 / 代码块 / 图表，或 180000 个纯文本字符 | `R2`、`R16`、`R17` |

- **C4.1** — 每个上限在触及时都应当被报告；静默截断不符合规范。
- **C4.2** — 含图表的块在正文其余部分被虚拟化时仍应当保持真实布局，因为被跳过布局的图表无法报告自身尺寸。

### C5  可移植性

- **C5.1** — 扩展应当声明 `^1.71.0` 为最低宿主版本，且不得使用该版本之后引入的任何宿主 API。
- **C5.2** — 扩展本身应当与平台无关。唯一与平台绑定的部分是 XAML 渲染器，它需要 Windows 桌面运行时，且应当作为前置条件声明。
- **C5.3** — XAML 渲染器应当以框架依赖方式分发，不得自包含：包内不允许携带运行时。

### C6  可观测性

- **C6.1** — 由用户输入或环境导致的失败应当连同原因一起报告；静默的无操作不符合规范。
- **C6.2** — 测试断言应当咬住外部可观察的结果。只证明「某条规则或某条消息存在」的断言，不足以覆盖它所声称覆盖的需求。
- **C6.3** — 任何文档引用的实测数字都应当能由一条明确的命令复现；没有命令出处的数字属于估算，应当如此标注。

## 6. 缓期与排除

下表的每一行在[已知限制](limitations.zh-CN.md)里都有对应条目。两者不一致时，本表在**意图**上优先，已知限制页在**细节**上优先。

| 条目 | 现状 | 为什么不承诺 | 重新考虑的前置条件 |
|---|---|---|---|
| 编辑器与预览之间的滚动同步 | 未交付 | 需要预览并不产出的源映射协议；目录导航不依赖它（限制 1） | 宿主提供稳定的源映射契约 |
| 接管宿主的 Simple Browser | 公开扩展面无法做到 | 它是命令创建的面板，从不进入自定义编辑器竞争（限制 2） | 宿主提供「认领已有面板」的机制 |
| HTML 在放宽策略下渲染 | 已交付，附警告 | 浏览 HTML 本身就要求页面自带脚本能跑（限制 3） | 不适用：放宽是唯一可行的策略 |
| 六种视图类型接管默认打开方式 | 有意为之 | 浏览视图本来就该是双击落点（限制 4） | 用户显式切换文件关联 |
| 默认 Mermaid 缩放依赖宿主的图表扩展 | 有意的依赖 | 扩展抬高的是被贡献的默认值，而不是再打包一个渲染器（限制 5） | 打包一个渲染器，代价是项目已拒绝的体积成本 |
| XAML 渲染为静态快照 | 有意为之 | 对着实时数据求值并运行处理器需要把应用托管起来（限制 6） | 在意图 1 之下永不 |
| XAML 根类型必须已被编译 | 取决于环境 | 只存在于源码中的类型无法承载（限制 7） | 先把项目编译一次 |
| 编辑框没有语法高亮 | 有意的取舍 | 纯文本表面才能保证与源码逐字符一致（限制 8） | 一个能保证同样一致性的可嵌入编辑器 |
| 只读模式跳过扩展自身的浏览视图 | 有意为之 | 截断一份要渲染的文档只会产出残缺渲染（限制 9） | 不适用 |
| 只读模式在切换编辑器时替换一次标签页 | 已知行为 | 该模式改写文件关联，切换时必然发生一次替换（限制 10） | 宿主提供「直接以指定编辑器打开文档、不重载」的 API |
| `atime` 与权限位恒显示占位符 | 宿主限制 | 宿主的文件元数据不暴露这两项（限制 11） | 宿主暴露这两项的 API |
| 基于字体的图标主题不回退 | 已知行为 | 只解析矢量形式的图标定义（限制 12） | 解析字体字形映射 |
| 内置资源管理器命令是手工维护的清单 | 已知行为 | 宿主要暴露可枚举清单（限制 13） | 宿主提供可枚举自身命令及参数的 API |
| 子树文件操作是自研的 | 有意为之 | 宿主不把自身的操作暴露给复用（限制 14） | 不适用 |
| 3D 只解析拓扑，不移植图表库的渲染 | 有意为之 | 2D 矢量输出无法直接变成可旋转场景；3D 需要的是拓扑（限制 15） | 一个保持拓扑的 3D 导出器 |
| 裸 ASCII 树识别保守 | 有意为之 | 猜得太多会凭空造出读者从未写过的图（限制 16） | 面板里提供消歧入口 |
| 3D 元素与节点上限 | 有意为之 | 布局与渲染成本有界（限制 17、C4） | 针对大图的性能测量工作 |
| 3D 场景需要 3D 上下文 | 取决于环境 | 二维投影会承诺另一个产品（限制 18） | 不适用 |
| 虚拟组没有磁盘对应物 | 设计如此 | 组只负责命名与归类，它不是目录（限制 19） | 不适用 |
| 工作区外的绝对路径不随机器迁移 | 已知行为 | 工作区之外没有占位符锚点（限制 20） | 一套可移植的锚点方案 |
| 外部并发编辑：最后写入者获胜 | 已知行为 | 写前比较已加入，但仍存在时间窗（限制 21） | 存储格式内引入加锁协议 |
| 符号链接、权限与多根工作区边界 | 部分已验证 | 所列情形已在真机验证；远程文件系统未验证（限制 22） | 具备远程文件系统的环境 |
| 资源树规模上限 | 有意为之 | 读取与渲染成本有界（限制 23） | 不适用 |
| 独立 Mermaid 预览依赖宿主的图表扩展 | 有意为之 | 复用一种渲染行为，而不是维护两种（限制 24） | 不适用 |
| 一个 Mermaid 文件即一张图 | 设计如此 | 文件即文档，一个文件一个场景（限制 25） | 出现多场景的文件格式 |
| Mermaid 文件的 3D 浏览共享解析器限制 | 已知行为 | 同一个解析器，同一份覆盖（限制 26） | 解析器覆盖工作 |
| HEIF / HEIC / TIFF / JXL 与若干视频容器 | 有意为之 | 解码器要花掉数兆字节，改为明确兜底（限制 27） | 运行时自带该解码器 |
| 多语言编辑字体与像素级外观 | 未验证 | 若干改动是按数值验证的，没有做渲染像素对照（未验证 1） | 并排渲染对照 |
| 嵌套结构上的段落边界精度 | 未验证 | 结束行由下一个块的起始行推断；嵌套是最不精确的情形（未验证 2） | 按嵌套类型逐项真机核对 |
| 整条工作区写入路径、外部贡献的资源管理器命令、本地化是否被拾取 | 未验证 | 有单元测试，但未在真实产品中逐项点击（未验证 3、4、5） | 真机演练 |
| 只读标签页在慢盘、大文件与预览标签下的替换时机 | 未验证 | 替换路径被跑到过，但不在这些条件下（未验证 6） | 分别开关一次预览标签并计时 |
| 超大目录与网络路径 | 未验证 | 没有可用的此类环境（未验证 7、14） | 具备大型共享目录的环境 |
| 图标主题语言桥的覆盖 | 未验证 | 扩展与语言的对应表未逐项比对（未验证 8） | 穷尽式比对 |
| 大图下的 3D 性能，以及较少见图种的视觉正确性 | 未验证 | 布局有单元测试；真机样本规模很小（未验证 9、10、11） | 大图测量 |
