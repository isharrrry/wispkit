## Markdown 视图（`wispkit.markdown`）

### 界面组成

```text
┌──────────┬──────────────────────────────────────────────┐
│  目录树   │  正文（内置 Markdown 预览同款排版）              │
│  h1..h6  │                                              │
│  （可拖宽/ │  代码块 / 表格 / mermaid / drawio / 图片       │
│   可收纳） │                                              │
└──────────┴──────────────────────────────────────────────┘
```

工具栏图标是内联 SVG sprite：标记里带 `width` / `height` 兜底，并在外部样式表之前内联一组最小关键样式。因此打开 Markdown 的瞬间不会出现「图标突然变得很大、加载完再跳回正常」的闪烁。

### 目录导航

- webview 内按 `h1..h6` 建树，**不依赖 `data-line` 源映射** —— 因此不需要编辑器↔预览的滚动同步协议。
- 滚动时跟随高亮当前章节；点击条目跳转并聚焦。
- 目录栏可拖拽调宽，**双击分隔条复位**；可一键收纳（收纳后正文占满）。
- 默认收录 Markdown 规范支持的全部六级标题（`h1..h6`）；`wispkit.toc.depth` 可收窄（默认 6），`wispkit.toc.enabled` 可整体关闭。

### 正文缩放与查找

- 工具栏提供 `− / 百分比 / +` 三级控件，共 13 个固定档位（50%–300%，含 100%）；点百分比回到 100%。`Ctrl+-` / `Ctrl+=` / `Ctrl+0` 与 `Ctrl+滚轮` 等价。缩放只作用于正文层，目录与工具栏不跟着放大；档位按文档记住，下次打开沿用。缩放会同时补偿 mermaid / drawio 的尺寸测量（它们会把 `getBoundingClientRect()` 的结果写回 CSS 像素，祖先 `zoom` 不补偿就会被放大两次）。
- `Ctrl+F` 呼出右上角查找栏：输入即高亮全部命中并显示 `当前/总数`；`Enter` / `Shift+Enter`、`F3` / `Shift+F3` 跳转，`Aa` 切换区分大小写，`Esc` 关闭并清除高亮。`Ctrl+F` 前若在正文里选中了文字，会直接用它预填查询。
- 现代引擎用 CSS Custom Highlight API 登记 `Range`，**不改 DOM**；旧引擎（没有该 API）退回 `<mark>` 包裹可单节点高亮的命中。搜索不进入 mermaid / drawio 图块与 SVG，避免第三方脚本异步替换后 Range 失效。

### 大文档性能

正文元素约 4000 个、或表格 / 代码块 / 图块约 40 个、或纯文字超过 18 万字时，正文层自动进入虚拟化：视口外的顶层块用 `content-visibility: auto` 跳过排版与绘制。**图块例外**——mermaid 扩展要在渲染后测量 SVG 才能定容器高度，跳过其布局会量到 0×0，因此含 svg / mermaid / drawio 的顶层块始终保持真实布局（CSS 类 `wispkit-virtualize-keep`），其余表格、代码块与段落照常跳过。目录的滚动高亮改为「缓存标题位置 + 二分查找」，只在宽度变化、正文重建或 `scrollHeight` 变化时重新测量；点目录跳到远处时对虚拟化块逐帧补正位置，直到连续 3 帧误差小于 1px（最长 1.2 秒；用户自己滚动或点击正文会立即取消补正）。查找期间临时关闭虚拟化，保证 `Range` 有布局、能准确高亮与跳转；关闭查找后自动恢复。

### 媒体右键菜单

| 右键对象 | 菜单项 | 点击后发生什么 |
|---|---|---|
| 普通图片 | 放大查看 / 另存为… / 复制路径 / 复制 Markdown 文本 | 另存为走系统保存对话框；复制路径取绝对路径；复制 Markdown 文本取原文里的 `![alt](src)` |
| mermaid 图 | 放大查看 / 另存为 SVG… / 复制源码 | 复制源码取 ` ```mermaid ` 围栏内的原文 |
| drawio 图 | 放大查看 / **用 Draw.io 编辑器打开** / 另存为 SVG… / 复制源码 | 见下节 |

「放大查看」是**占满主窗口的模态框**，支持滚轮缩放与按住右键拖动平移（与图片视图同一套 panzoom 实现），`Esc` 或点击遮罩关闭。

前端只上报 `{ action, kind, index, alt?, src? }`；**真实路径与源码由宿主回 Markdown 原文取**（`src/media/parse.ts`，纯函数，20 条单测）。图片额外用 `alt` 交叉校验，索引错位也能救回。

### drawio 就地编辑

drawio 扩展 1.17.0 已把编辑交给新版 Markdown 编辑器（`markdown.codeBlockEditorProviders`），自定义编辑器里没有那套宿主，所以 Wispkit 自己接：

1. 从前端上报的 index 定位代码块，抽出 XML 内容；
2. 写成临时 `.drawio` 文件；
3. `vscode.openWith(..., 'hediet.vscode-drawio-text')` 打开；
4. 保存时**按内容重新定位**回写原文 —— 即使文档在别处被编辑过，也不会错位替换。

### 主题三态（浅色 / 跟随主题 / 深色）

工具栏右侧是一组三段式图标按钮：左「浅色」、中「跟随主题」、右「深色」，默认选中间。

- **跟随主题**：不强制任何颜色，继续读 VS Code 当前颜色主题的变量；VS Code 切换明暗时正文与图表一起变。
- **浅色 / 深色**：只强制 **Markdown 浏览器** 的明暗（`<html>` 上的 `wispkit-theme-*` 类 + 带 `!important` 的 `--vscode-*` 覆盖），不改 VS Code 自身主题，也不影响图片 / HTML / XAML 视图。调色板取 VS Code 默认 Light+ / Dark+；「强制」的含义就是不跟随，因此用户自定义颜色主题的配色不会带过来。
- 状态是**全局**的：在一个 Markdown 标签页里切换，所有已打开的 Markdown 视图立即同步；新视图从 `globalState`（`wispkit.markdown.themeMode`）继承，重启 VS Code 后仍保留。它**不是当前 md 文档**的属性。
- 强制模式会同时改写 `body` 的 `vscode-light` / `vscode-dark` 类，让内置 `markdown.css` 的边线规则与 mermaid 预览扩展的图表配色保持同一明暗；切回「跟随主题」时还原宿主真实类别。

### 编辑模式（光标段落就地编辑）

工具栏「编辑」是个滑动开关（`role="switch"`，开关态只看 `aria-checked`）。打开后**点正文任意一段**，那一段原地变成 `<textarea>`，其余段落保持渲染后的样子 —— 不分栏、不新开编辑器。

| 操作 | 行为 |
|---|---|
| 单击某一段 | 该段原地变成编辑框，内容是这一段对应的 Markdown 原文（verbatim，不补分隔空行） |
| `Enter` | 插入空行（`\n\n`）—— 单个回车在 CommonMark 里只是软换行，补成空行才真的分出新段落 |
| `Shift+Enter` | 段内软换行，留在同一段 |
| `Ctrl+Enter`（macOS `Cmd+Enter`） | 提交当前段：写回整篇源码并立即保存 |
| `Esc` | 放弃当前段的修改 |
| `Ctrl+S`（macOS `Cmd+S`） | 保存整篇；编辑框未提交时先提交 |

映射依据：内置引擎给每个块级 token 打 `data-line`（起始行），段落结束行按**下一个块的起始行减一**推断，末段以源码总行数兜底；区间左闭右开 `[start, end)`。这一层是纯函数（`media/shared/paragraph.js`），有单测覆盖 —— 嵌套结构（列表项、引用块、代码块内部）的边界是本方案最不精确的地方。

保存经 `WorkspaceEdit` 整篇替换，进正常撤销栈。整篇源码只在**进入编辑模式时**向宿主索取一次（`wispkit.requestSource`），纯预览不背这份开销。

### 消息契约

| 前端 → 宿主 | 载荷 | 宿主返回 |
|---|---|---|
| `wispkit.requestSource` | 无 | 源码文本 |
| `wispkit.render` | `requestId`、`text` | `{ requestId, html }`（宿主保留分支；段落编辑提交后由 `onDidChangeTextDocument` 自动重渲染，前端已不再主动发） |
| `wispkit.save` | `requestId`、`text` | `wispkit.saveResult { requestId, ok }` |
| `wispkit.media` | `action`、`kind`（`image`/`mermaid`/`drawio`）、`index`、`alt?`、`src?`、`data?` | 无（宿主自行执行） |
| `wispkit.openLink` | `href`（`<a>` 的**原始属性值**，不是浏览器解析后的绝对 URL） | 无（宿主相对文档目录解析后打开） |
| `wispkit.setTheme` | `mode`（`light` / `auto` / `dark`） | 宿主写入 `globalState` 后向**所有** Markdown 视图广播 `wispkit.theme { mode }` |

### 正文排版

内置 `markdown.css` 的字体/字号/行高读的是 `--markdown-font-family` / `--markdown-font-size` / `--markdown-line-height` 三个变量。Wispkit 把 `markdown.preview.*` 的设置喂给它们，所以正文与内置预览逐字一致。

换算照抄内置（`documentRenderer.ts:211-213`）：`fontSize` 拼 `px`，`lineHeight` **原样输出**（数字表示字号倍数，内置默认 1.6）。给 `lineHeight` 拼 `px` 会让行高变成 `1.6px`，正文、代码块、目录一起重叠 —— 这是实际踩过的坑，`src/test/markdownPage.test.ts` 有防回归断言。**不要**给 `body` 写 `font` 简写，那会覆盖这三个变量。

## 图片视图（`wispkit.image`）

| 手势 | 行为 |
|---|---|
| 滚轮 | 直接缩放（不用按 Ctrl），以**光标位置为锚点**，视图中心不跳；`wispkit.image.wheelZoom=false` 时退回"需按 Ctrl" |
| 按住 `wispkit.image.dragButton`（默认右键）拖动 | 平移 |
| 双击 | 在「适应窗口」与「100%」之间切换 |
| 放大 ≥ 3× | 渲染切换为 `pixelated`，避免糊成一团 |

缩放步长由 `wispkit.zoom.wheelStep` 决定（默认 1.1），同一套 panzoom 也用于 Markdown 模态框与 XAML 渲染。

### 格式覆盖

- **内核直接解码**：PNG / JPG / JPEG / JFIF / BMP / GIF / ICO / WebP / AVIF / APNG / **SVG**。
- **SVG 走矢量缩放**：不写 `transform: scale()`，而是改 `<img>` 的布局宽高（panzoom 的 `scaleMode: 'box'`），放大时浏览器按矢量重画，不会变糊；右下角提示会标注「矢量图」。
- **没有内核解码器的格式**：HEIF / HEIC / TIFF / JXL。Chromium 不带这些解码器，引入 libheif 等 WASM 解码器要约数 MB，本扩展按「不加大依赖」的约定不打包。这几种文件仍由图片视图接管，但页面显示**解码失败原因**，并提供两个按钮：
  - 「用系统默认应用打开」—— 交给操作系统（Windows 装了 HEIF 扩展即可用照片应用看）；
  - 「复制路径」—— 复制绝对路径，便于自行转码或另开工具。
- 文件损坏或扩展名与实际内容不符时，同样落到这个兜底面板，不会只显示一片空白。

## 视频视图（`wispkit.video`）

| 操作 | 行为 |
|---|---|
| 双击常见视频 | 进入视频视图，使用 Chromium 原生 `<video controls>` 播放，不自带播放器、不引第三方库 |
| 播放 / 暂停 / 进度 / 音量 / 全屏 | 全部交给原生控件；双击画面切换全屏 |
| 右上角「系统播放器打开」 | 把文件交给操作系统默认播放器（`vscode.env.openExternal`） |
| 右上角「复制路径」 | 复制绝对路径到剪贴板 |
| 切换到其它标签页 | 自动暂停，避免后台继续出声 |

- **能否播放取决于运行时的编解码器**：H.264 / AAC 的 MP4、VP8 / VP9 的 WebM 通常可直接播放；MKV / AVI / WMV / FLV / RMVB 等容器多数只有兜底。页面在 `<video>` 报 `MEDIA_ERR_SRC_NOT_SUPPORTED` 时显示原因与「系统播放器打开」提示，不会静默黑屏。
- 状态栏显示「格式 · 分辨率 · 时长」，时长未知（流式文件）时显示「未知时长」。
- **没有注册 `.ts` / `.mts`**：它们是 TypeScript 源码的扩展名，注册成视频会把所有 TS 文件抢走；MPEG-TS 只覆盖 `.m2ts`。
- CSP 用 `media-src ${cspSource}` 放行 webview 资源源，脚本仍然只认 nonce；视频文件通过 `asWebviewUri` 直接加载，不复制、不转码。

## HTML 视图（`wispkit.html`）

- 采用**宽松 CSP**：放行内联脚本与 http(s) 资源 —— 浏览 HTML 本身就需要页面自带脚本能跑。
- 把 `href="vscode://file/<路径>[:<行号>]"` 改写成 `command:vscode.open?<args>`，并开启 webview 的 `enableCommandUris`；未改写的 `vscode://` 也在宿主白名单内。这是**无脚本兜底**：页面自己的 CSP 拦掉注入脚本时，这两类链接仍然可用。
- 注入 `media/dist/html.js`（`<script defer>`）做**链接路由**：在 `document` 冒泡阶段截住 `<a>` 点击，把原始 `href` 经 `wispkit.openLink` 送回扩展。相对链接不会因为 `<base>` 被解析成 webview 资源 URL 而跳系统浏览器；`#锚点`、`command:` 以及外壳本就支持的 scheme（`http(s)` / `mailto` / 非 file 的 `vscode:`）不拦。
- 页面自己的 click 处理先执行；它调过 `preventDefault()` 的链接不会被抢（SPA 常用）。

## XAML 视图（`wispkit.xaml`）

### 界面

左侧源码栏（可编辑）+ 右侧渲染图，中间分隔条可拖动。源码栏可隐藏（`wispkit.xaml.codeVisible`），宽度受 `wispkit.xaml.codeWidth` 控制（默认 460px）。

- 源码区有**自研轻量高亮**：高亮层与 `<textarea>` 叠放，textarea 文字透明只留光标，因此输出必须与输入**逐字相同**（多一个少一个字符光标就会偏）。
- 渲染图支持滚轮缩放与拖动平移；点图可进全屏模态框。
- 改动后保存，写回原 `.xaml` 文件。

### 渲染调用链

1. 从 `.xaml` 所在目录**逐级向上**找 `bin/(Release|Debug)/<tfm>/*.dll`；
2. 调外部 .NET 进程，契约冻结为 `<renderer> render <in.xaml> <out.png> [--assembly <dll>]... [--width N] [--height N] [--class <T>] [--json]`；扩展侧只用到 `--assembly` 与 `--json`，stdout **最后一行**的单行 JSON 是唯一结果通道；
3. 根类型按 `--class`（扩展未传）→ XAML 的 `x:Class` → **根元素对应的 WPF 基类**（`<Window>` → `System.Windows.Window`、`<UserControl>` → …）依次尝试，每个候选都配「原样」与「去掉 `x:Class` + 事件处理器」两种文本变体，再用 `XamlObjectWriterSettings.RootObjectInstance` 让 XAML 往该实例上填内容（`mode=rootObjectInstance`）。真实窗口的构造函数普遍依赖 DI/App 单例、`new` 不出来，所以基类承载是主力路径；全都走不通才回退 `XamlReader.Parse`（`mode=parse`）；
4. 结果 PNG 回传到页面。

渲染失败时页面显示错误面板与常见原因提示，不会白屏。

## Mermaid 文件视图（`wispkit.mermaid`）

双击 `.mmd` / `.mermaid` 进入。宿主把整份源码交给 VS Code 内置的 Mermaid 预览脚本渲染，页面只有一条工具栏：

- 顶部徽标显示图种与节点 / 边数量（与 3D 面板共用 `src/graph3d/mermaid.ts` 的解析结果）；
- **3D 可视化浏览**：把这张图交给 `wispkit.graph3d`，下拉里只有 `1. 标题 · 图种 · N 节点 / M 边`；
- **源码**：在侧边用普通文本编辑器打开同一文件；
- **刷新**：重新读取文件并重渲染；编辑器里的文本变化会在 300 ms 防抖后原地更新。

图表由内置脚本在可用宽度内**水平居中**（与 Markdown 预览里的 Mermaid 图同一条渲染管线）：页面只保证 `.mermaid-wrapper` 占满整行，不再额外做 flex 居中 —— 否则内置脚本按 `(容器宽 − SVG 宽) / 2` 设的 `transform` 会被叠加两次，图会整体靠右。

没有可用的 Mermaid 预览脚本（例如 VS Code 版本过旧）时退化为源码模式：工具栏、3D 入口与状态徽标不变，正文改为 `<pre>`，顶部提示条说明原因。

消息契约：前端 → 宿主为 `wispkit.mmd.refresh` / `wispkit.mmd.openSource` / `wispkit.mmd.open3d`；宿主 → 前端只有 `wispkit.mmd.update { source, status, hint? }`。前端收到更新后改写 `.mermaid` 容器的 textContent，并派发内置脚本监听的 `vscode.markdown.updateContent`。

## 只读文本视图（`wispkit.text`）

- 全局只读模式开启后，`.ts` / `.json` / `.txt` / `.log` 等（由 `wispkit.readonly.extensions` 决定）打开时换成只读预览。
- 只读**文件头若干字节**（`wispkit.readonly.previewBytes`，默认 64 KB），再按 `wispkit.readonly.previewLines`（默认 800 行）截断。
- 页面含行号与**自研通用语法高亮**（注释/字符串/数字/关键字级别，非 TextMate 精确着色）。
- 右下角悬浮「解锁编辑」：点了改用原生编辑器打开（可编辑），并在本次会话内放行该文件。
- 已被 Wispkit 接管的浏览视图（Markdown / HTML / XAML / 图片）**不受只读模式影响** —— 它们本来就是浏览视图，而截断 Markdown 会渲染出残缺结果。

## 自定义资源管理（`wispkit.resourceTree`）

### 入口与界面

活动栏左侧的 **Wispkit** 图标（`media/wispkit-activity.svg`）打开「自定义资源管理」视图。它是原生 `TreeView`（不是 webview），所以外观、展开 / 折叠、拖拽与右键菜单都跟随 VS Code 当前主题。

- **没有工作区**：视图正文提示「请先打开一个工作区文件夹；资源树会保存在第一个工作区的 `.WispkitView/resource-tree.json`。」
- **空树**：欢迎页给出「新建虚拟组」「添加文件夹」两个入口，并说明不会移动或删除磁盘文件。
- **视图描述**：标题右侧显示当前存储文件的工作区相对路径；工作区外或非 `file` 工作区显示绝对路径 / URI。
- **配置错误 / 读取失败**：视图正文常驻诊断信息（占位符无法解析、JSON 非法、路径是目录…），当前树保持不变。

### 两种节点：虚拟组 vs 文件夹

| 节点 | 图标 | 对应磁盘 | 说明 |
|---|---|---|---|
| 虚拟组（`group`） | `folder-library` | **不对应任何磁盘文件夹** | 只用于命名与归类；可包含虚拟组或文件夹；单击明确提示不能浏览 |
| 文件夹（`folder`） | `folder`；异常时 `warning` | 真实目录，`path` 保存绝对路径或工作区占位符 | 单击在子树面板打开；可包含子节点 |

- 两种节点**都可以有子节点**，因此「任意层级」由同一套规则表达。默认上限：总节点 2000、单层子项 200、深度 12。
- 文件夹的 `description` 显示工作区相对路径（工作区外的文件夹显示绝对路径）；路径不存在 / 指向文件 / 占位符解析失败时分别显示 `⚠ 文件夹不存在` / `⚠ 不是文件夹` / `⚠ 路径无法解析`，图标变警告色。
- 重命名、移动、删除只作用于这棵树：**不会重命名、移动或删除磁盘上的任何文件**。

### 视图标题命令

| 命令 | 位置 | 行为 |
|---|---|---|
| 新建虚拟组 | 标题栏 | 在根或选中节点下新建虚拟组 |
| 添加文件夹 | 标题栏 | 打开系统文件夹选择器；可多选，逐个加为文件夹节点；非目录条目跳过并提示 |
| 刷新 | 标题栏 | 重新读取 JSON；非法 JSON / 读取失败时保留当前树并提示，不会覆盖文件 |
| 导入资源树… | 标题栏溢出菜单 | 选择 JSON，确认后**整体替换**当前树；非法文件在确认框之前就被拒绝 |
| 导出资源树… | 标题栏溢出菜单 | 把当前树写到用户选择的 JSON 文件 |
| 打开资源树 JSON | 标题栏溢出菜单 | 打开当前存储文件；文件不存在时先写入当前树（初次使用即空树） |

### 条目右键命令

| 命令 | 作用于 | 行为 |
|---|---|---|
| 浏览文件夹 | 文件夹（悬停内联图标 / 右键菜单） | 在子树面板打开该目录 |
| 复制路径 | 文件夹（右键菜单） | 复制该文件夹的绝对路径到系统剪贴板；只解析占位符，不要求目录当前存在（离线网盘也能复制） |
| 在内置终端中打开 | 文件夹（行尾内联图标 / 右键菜单） | 在 VS Code 集成终端里打开该目录，终端标签用显示名 / 别名 |
| 系统终端打开 | 文件夹（右键菜单子菜单） | 打开独立于 VS Code 的系统终端窗口。Windows：命令提示符 (cmd)、PowerShell、命令提示符 (管理员)、PowerShell (管理员)；macOS：Terminal.app；Linux：按 gnome-terminal → konsole → xfce4-terminal → xterm 自动回退。管理员选项会弹出 UAC 提权确认 |
| 在 VS Code 中打开 | 文件夹（右键菜单） | 把该目录作为工作区在**新窗口**打开，不替换当前窗口 |
| 在系统资源管理器中打开 | 文件夹（右键菜单） | 交给操作系统打开该目录（Windows 为资源管理器） |
| 新建虚拟组 / 添加文件夹 | 组或文件夹 | 在该节点下新建子节点 |
| 重命名 | 组或文件夹 | 只改树里的显示名，不重命名磁盘目录 |
| 移动到… | 组或文件夹 | 快速选择目标组 / 文件夹（含「根目录」）；拒绝移进自身或后代 |
| 上移 / 下移 | 组或文件夹 | 在同一父级内调整顺序 |
| 删除 | 组或文件夹 | 确认后从树里删除（含子树）；**不删除磁盘文件** |

资源管理器里右键**文件夹**还有「添加到自定义资源管理」，加到根目录。单选时输入显示名；多选时直接以文件夹名批量添加（不逐个弹输入框），文件等非目录条目跳过并汇总提示；同一批次内相同路径只加一次。

### 拖拽

| 来源 → 目标 | 行为 |
|---|---|
| 视图内条目 → 组 / 文件夹 | 移动节点（可多选一起拖）；目标位于节点自身或后代内部的不会被移动 |
| 视图内条目 → 空白处 | 移到根目录 |
| 资源管理器文件夹 → 组 / 文件夹 / 空白处 | 添加为文件夹节点；拖到容器内成为子节点；非目录条目跳过并提示 |

内部拖拽走私有 MIME（`application/vnd.code.tree.wispkit.resourcetree`），外部拖入走 `text/uri-list`；宿主在落点处会再次校验节点类型与环，非法移动不改动树。

### 存储与刷新

- 默认保存在**第一个工作区**的 `.WispkitView/resource-tree.json`；可用 `wispkit.resourceTree.file` 改（相对第一个工作区，支持 `${workspaceFolder}` / `${workspaceFolder:名称}` / `${workspaceFolder:序号}` 与绝对路径）。
- 文件是普通 JSON：`{ "version": 1, "roots": [...] }`。每次增删改移都会自动写回，写入采用「同目录临时文件 + rename」。
- **外部编辑后不会自动出现**：扩展没有监听这个文件，改完 JSON 要在视图标题点「刷新」。刷新会尽量保留展开 / 选中状态。
- 非法 JSON、目录、无权限：刷新失败并说明原因，当前树与文件内容都保持不变；修改 `wispkit.resourceTree.file` 后会自动重载新文件。

### 存储器区域（`wispkit.storage`）

「自定义资源管理」下方的 **存储器** 视图默认**收纳**（`visibility: "collapsed"`），点标题展开时才枚举系统设备，避免每次启动都拉 PowerShell。

| 层级 | 内容 | 说明 |
|---|---|---|
| 设备 | 物理磁盘、U 盘、网络位置、光盘 / 其他卷 | Windows 来自 `Win32_DiskDrive` / `Win32_LogicalDisk`；U 盘按 Removable / USB 标记使用 `plug` 图标；网络驱动器归入「网络位置」 |
| 分区 / 挂载点 | `C: 卷标`、`D: 卷标`、`Z:\`、`/mnt/share` | 有盘符 / 挂载路径的分区直接作为挂载点；未挂载分区显示为信息行，不会伪装成可浏览目录 |

- 挂载点条目与上方资源树的文件夹节点**外观与右键菜单一致**：`folder` 图标、单击在子树面板打开，右键提供浏览文件夹 / 复制路径 / 内联终端 / 系统终端打开 / 在 VS Code 中打开 / 在系统资源管理器中打开。重命名 / 移动 / 删除等只对 JSON 节点有意义的操作不会出现在系统卷上。
- 标题栏「刷新存储器」强制重新枚举；视图重新可见且缓存超过 30 秒时也会静默刷新（插拔 U 盘后无需重启）。
- 枚举失败（PowerShell 被策略禁用、容器内无 `/proc/mounts` 等）时视图正文显示诊断，并保留可重试的刷新入口；Windows 上 CIM 失败会退化为 `Get-PSDrive` 只列盘符。

## 子树面板（`wispkit.subtree`）

### 打开方式

资源管理器里每个**文件夹行**右侧两个图标：左边「展示」（`wispkit.wispkitView.open`）、右边「子树浏览」（`wispkit.subtree.open`）。两个命令都只在该行是文件夹时出现，且不在命令面板里出现。

**同一文件夹复用同一个面板**：重复点击只 reveal 已存在的面板，不会开一堆。

### 界面

```text
┌────────────────────────────────────────────────────────┐
│ 表头：名称 | 大小 | 类型 | 修改时间 | 创建时间 | 用户     │
├────────────────────────────────────────────────────────┤
│ ▸ 目录A                                                 │
│   ▸ 目录B                                               │
│     文件.txt                                            │
├────────────────────────────────────────────────────────┤
│ 右侧操作区：文件操作（剪切/复制/粘贴/重命名/删除/新建/比较）│
│             扩展命令（带来源徽标）· 自定义工具            │
└────────────────────────────────────────────────────────┘
```

- **懒加载**：展开某一层才读那一层，不一次递归整棵树。
- **列可配置**：严格按 `wispkit.subtree.columns` 顺序渲染；表头与数据行共用 `--wispkit-col-*` 变量保证对齐。取不到的属性显示 `-` 而不是崩（`atime`、POSIX 权限位恒为 `-`）。
- **排序**：点表头按该列排序，纯逻辑在 `src/subtree/sort.ts`。

### 右侧操作区的三类操作

| 类别 | 来源 | 说明 |
|---|---|---|
| 文件操作（native） | Wispkit 自研 | 剪切 / 复制 / 粘贴 / 重命名 / 删除 / 新建文件 / 新建文件夹 / 比较。**不自研就用不了**：内置 `filesExplorer.*` 命令不接受外部 URI 参数 |
| 扩展贡献命令 | 自动收集 | 遍历已装扩展的 `contributes.menus['explorer/context']`，执行前校验命令存在 |
| 内置白名单 | 手工列 | 执行前用 `commands.getCommands(true)` 校验；不存在就明说，不静默 |
| 自定义工具 | `wispkit.subtree.tools` | 支持 `${file}` `${dir}` `${name}` `${workspaceFolder}`；四种执行方式见下表 |

| `shell` | 行为 |
|---|---|
| `silent` | 后台执行，不弹窗 |
| `currentTerminal` | 写入当前活动终端 |
| `newTerminal` | 新建终端并写入 |
| `external` | 脱离进程启动系统终端窗口 |

**对象是「表格选中条目」而不是资源管理器选中条目** —— 右侧所有按钮都作用于子树面板里当前选中的那一行。

### 拖放

- **拖入**：把资源管理器里的文件 / 文件夹、文本、HTML、图片或链接拖到树或某个文件夹行上。
  - 能解析出源路径（`text/uri-list` 或 `text/plain` 里的绝对路径）→ 询问**复制 / 移动**；同名时再问**覆盖 / 自动重命名 / 取消**。移动优先 `workspace.fs.rename`，跨卷时退回复制 + 删除（删除进回收站）。
  - 只有内容、没有源路径的 File（系统直接拖入）→ 询问**复制 / 移动**；受 webview 限制拿不到源路径，选移动会明确提示只能复制。
  - 文本 / HTML / 图片 data URL / 链接等「其他类型资源」→ 先选**存储类型**（如 `.txt` / `.md` / `.url`，一个资源支持的多种类型都会列出来），再填**文件名**；默认名取内容第一段有意义的文字（HTML 优先 `<title>`，URL 取路径最后一段或主机名），抽不出就留空，不强行编名字。
- **树内 Ctrl 拖动 = 移动**：拖动条目（同面板内拖动，或在左右两个子树面板之间互拖）时按住 **Ctrl**（macOS 为 **Cmd**），直接按「移动」执行，不再弹「复制 / 移动」。判定同时看 dragstart 与 drop 的键态 —— 先按下 Ctrl 再拖、松手前已放开也算；目标文件夹高亮会从复制蓝变成移动绿。同名冲突仍会问**覆盖 / 自动重命名 / 取消**。**系统拖入不适用**：Windows 资源管理器里 Ctrl 本身是「复制」，反过来解释会误删源文件。
- **拖出**：拖拽由 Pointer Events 实现，**不使用 HTML5 原生拖拽** —— VS Code webview 里 `draggable=true` 会进入原生 OLE 拖拽循环并把主进程卡死（拖到系统资源管理器时必现）。拖到树内 = 复制 / Ctrl 移动；拖到 webview 之外松手时，宿主会命中光标下的资源管理器窗口并复制 / 移动到该窗口的当前目录（按住 Ctrl = 移动，多选完整带出）；如果光标不在资源管理器窗口上，则把文件放入 Windows 剪贴板，可在资源管理器里 `Ctrl+V` 粘贴。
- **系统文件拖入不需要按 Shift**：VS Code 的 webview 默认会把「全是文件」的拖拽转交编辑器（临时把 iframe 设为 `pointer-events: none`），过去只有按住 Shift 才能让页面收到 drop。现在前端在 document 的**捕获阶段**拦截纯文件拖拽：`dragenter` 先 `preventDefault()`（pre script 看到 `defaultPrevented` 会直接返回，不再通知宿主禁用 iframe），同时 `stopPropagation()` 让 dragover / drop 到不了 window 上的转发逻辑。文件可以直接拖进树里；OS 拖入同样因为没有源路径而只能复制。

### 消息契约

| 前端 → 宿主 | 说明 |
|---|---|
| `wispkit.subtree.read` | 读取某一层目录（懒加载） |
| `wispkit.subtree.sort` | 按列排序 |
| `wispkit.subtree.command` | 执行扩展/内置命令 |
| `wispkit.subtree.fileAction` | 文件操作，具体分支 `cut` / `copy` / `paste` / `rename` / `delete` / `newFile` / `newFolder` / `compare` |
| `wispkit.subtree.tool` | 执行自定义工具 |
| `wispkit.subtree.open` | 打开/定位条目 |
| `wispkit.subtree.drop` | 拖入资源的原始内容（`targetDir` + `files` 字节 + `strings`），宿主负责询问与落盘；`internalDrag` + `moveRequested` 表示「来自子树内部拖拽且按着 Ctrl/Cmd」，宿主据此跳过复制/移动询问、直接移动 |

## 3D 可视化浏览（`wispkit.graph3d`）

### 打开方式

| 入口 | 行为 |
|---|---|
| 资源管理器里右键 `.md` / `.markdown` / `.mmd` / `.mermaid` → **3D 可视化浏览** | 菜单项只在这些扩展名上出现；打开当前文件（`.mmd` / `.mermaid` 整份文件解析为一张图） |
| 命令面板 → `Wispkit: 3D 可视化浏览` | 优先用活动 Markdown 编辑器 / 标签；活动文件不是 Markdown / Mermaid 时提示只支持这些扩展名；没有活动文件时提示先右键或打开一个 Markdown / Mermaid 文件 |

**同一文件复用同一个面板**：再次执行只 reveal 已存在的面板，不会叠加新标签。这个面板是 `webviewPanel`（不是自定义编辑器），不参与打开方式竞争。

### 界面组成

```text
┌──────────────────────────────────────────────────────────────────────────────────┐
│ 左图元素 [下拉]  右图元素 [下拉] │ 合并左右 重置视角 刷新 │ 布局 [下拉] 间隔 [滑杆] 1.00× [x]显示数据流名称 状态 │
├───────────────────────────────────┬──────────────────────────────────────────┤
│ 左侧：名称 + N 节点 · M 边          │ 右侧：名称 + N 节点 · M 边                │
│        3D 场景                      │        3D 场景                            │
│  左键拖动旋转 · 右键拖动平移 · 滚轮缩放 · 悬停节点看注释                        │
└───────────────────────────────────┴──────────────────────────────────────────┘
```

- **左右下拉**：每项显示 `序号. 名称 · N 节点 / M 边`，另有「（不选）」。初始左侧选第 1 个图元素、右侧不选；只选一侧时该侧占满整个面板。
- **合并左右**：两侧都选中才可用。合并后左右栏与分隔条隐藏，只显示「合并视图」，按钮变「取消合并」。
- **重置视角**：把相机复位到能看全整张图的方向与距离。
- **刷新**：重新读取并解析当前文件。仍然存在的左右选择按 id / name 恢复；用户主动选的「不选」保持不变；文档从没有图元素变成有图元素时自动选第 1 个。刷新按钮在 8 秒后自动恢复可用（避免请求丢失时永久禁用）。
- **布局**：下拉可选「自动（按拓扑）」「紧凑分层」「互斥 · 紧凑分层」「Louvain 壳内 FR-3D」「径向树」「分层环」「3D 力导向」「互斥 · 3D 力导向」，切换后立即重新布局。两种「互斥」算法在合并视图里把左右两张图各自的核心节点推到布局左右两端，同名合并出来的融合节点留在中间（一侧是另一侧超集时，融合节点留在原地、另一侧的独占节点被推到外侧），状态行会标出「左核 / 右核」；没有合并（单图）时自动退回对应的基础算法。
- **间隔**：0.25×–3×，拖动停下约 90 ms 后重新布局；相机距离按新的包围半径等比缩放，整张图仍在视口内。
- **显示数据流名称**：默认勾选。勾选时每条边中点上方显示边名称（与节点气泡同款 Sprite 文字）；悬空边的名称移到靠近悬空端的一侧，避免长名称压住真实节点的气泡文字。取消勾选立即隐藏，不重新布局。左右分栏与合并视图同步生效。
- **void 悬空占位**：Mermaid 节点标签恰好是 `void`（忽略首尾空白与大小写，例如 Drawcode 导出「对侧未创建」的模块交联图）时不画气泡；与它相连的流变成从真实节点伸向空处的**悬空边**。悬空方向会避开已有连线与附近气泡，同一节点周围的多条悬空边按角度散开，长度取在常规边距附近；箭头保持原 source → target 方向（`void → 节点` 指向真实节点，`节点 → void` 指向悬空端）。下拉与统计的节点数不含 `void`，边数照常包含悬空边，状态行追加「N 悬空」。孤立或只与其它 `void` 相连的节点保留；ASCII 树里的 `void` 不做此处理。
- **悬停注释 tooltip**：鼠标移到带注释节点的气泡区域内时，光标旁显示「节点名称 + 注释」；移出气泡、开始拖动或滚轮缩放时自动隐藏。没有注释的节点不弹 tooltip。
- **长名称完整显示**：名称较长且没有手动换行时，先把空格、斜杠、反斜杠、横杠换成换行；再按气泡可用区域的宽高比自适应折行。主文字**一个字符都不会被截掉**，纹理超过 2048 时只缩小字号；文字块按气泡球的内接矩形缩放，四角都在气泡轮廓内。
- **图片气泡**：节点名称写成 Markdown 链接 `[文字](图片路径)`（也接受 `![文字](路径)`），且路径指向存在、可解析的图片（png / jpg / jpeg / jpe / gif / webp / bmp / ico / avif，单张 ≤ 16 MB）时，气泡里**不显示文字**，改为显示图片。图片按原始宽高比缩放，四角正好落在气泡球面上，并始终面向相机；文件不存在、不是图片扩展名、文件头不可识别或前端解码失败时自动退回显示文字。相对路径基于当前 Markdown / Mermaid 文件所在目录，支持 Windows 绝对路径（含盘符 / UNC）与 `file:` URI。
- **分隔条**：两侧都选中时出现，拖动调整左右占比并夹在 **15%–85%**，**双击复位 50% / 50%**。
- **状态栏**：显示解析结果、合并了多少个同名节点、刷新与错误信息；错误用错误色。
- 每个 3D 场景底部有操作提示；没有 WebGL 时该场景显示错误层而不是白屏。

### 图元素命名规则

- 只收集两类元素：围栏代码块里的 **Mermaid**（` ```mermaid `），以及围栏或正文里的 **ASCII / 制表符树**。独立 Mermaid 文件（`.mmd` / `.mermaid`）整份解析为一个图元素，名字优先取文件里的 `title`，其次文件名。
- 名字优先级：Mermaid 的 `title`（frontmatter 或 `title` 指令）> **最近的 Markdown 标题**（`#`..`######`，围栏里的标题不算）> 图里第一个非空节点标签 > 文件名兜底。
- 名字末尾追加图种，例如 `构建流程 · 流程图`、`src · ASCII 树`、`登录时序 · 时序图`；未知 Mermaid 图种显示 `Mermaid 图`。
- **同名元素自动追加 `(2)`、`(3)`**，下拉框里永远能区分。
- 面板标题显示 `3D：文件名（N）`，N 为图元素数量；下拉项额外带节点 / 边计数。

### 条目注释识别

注释会挂到节点上，3D 里悬停气泡时用 tooltip 显示；不会混进节点标签，也不参与同名合并的比较。

- **ASCII / 制表符树**：
  - 行尾注释：`├── src   # 源码目录`、`└── main.ts   // 入口`。注释标记必须有前导空白，因此 `C#`、`F#` 等标签里的 `#` 不会被切开。
  - 整行注释：`│   # 这是注释`（可带树形前缀），挂到最近一个节点。
  - 折行注释：注释行没重复写 `#` 时，只有缩进列 **≥ 注释起始列** 才并进注释；否则仍按标签折行处理，避免把长标签误吞成注释。
  - 连续多行注释用 `\n` 连接；单节点最多保留 12 行 / 1200 字符。
- **Mermaid**：`%% 注释` 整行注释挂到**下一行新建**的节点；语句末尾的 `%% 注释` 属于同一行新建的节点；连续整行注释合并为多行。`%%{init: …}%%` 等指令不算注释。注释落在多个新建节点上时（例如 `A --> B`）会同时挂给它们。
- **合并视图**：同名节点合并时，两侧注释按行去重后合并，tooltip 里能看到双方内容。

### 合并同名节点规则

- **只跨左右两个图元素合并**；同一张图内部的同名节点不合并，避免把重复出现的普通节点误当实体。
- 名称比较：`trim`、连续空白压成一个空格、去掉首尾引号 / 反引号、大小写不敏感；中文不受大小写影响。
- 合并后保留左侧节点（id 与标签），右侧同名节点的 `detail` 去重后并入（最多 24 条），`comment` 按行去重合并；右侧未匹配节点用 `r:` 前缀重新分配 id，右侧分组 id 也做同样重映射，避免撞车。
- 边全部保留：左侧原样，右侧端点重映射；`source + target + label + dashed` 完全相同的边去重，因此两个图会通过共享节点连成一个整体。
- 没有同名节点时，两侧仍放进同一个 3D 场景但保持独立；状态栏与统计会明确给出实际合并数量（0 时也会说明）。
- 合并视图的统计行会带 `已合并 N 个同名节点…` 或 `两侧没有同名节点…` 的说明。
