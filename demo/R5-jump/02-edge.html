R5-02 跳转边界（观察项集合）

这一份不是通过/失败题，而是把改写逻辑的边界一次性摆出来。 每条都写了"我预期的行为"，你只需要核对实际是否一致。

先确认基线：如果 这一条基础跳转都点不动， 就不用往下看了——先解决"HTML 视图 + enableCommandUris"这条主通路。

1. 行号 = 0（预期：只打开文件，不定位）

target-simple.md:0

改写逻辑里 line < 1 会被当作"没有行号"，所以只传资源、不传 selection。 预期：文件打开、光标不动。若报错说明这个分支写错了。

2. 行号越界（文件只有 20 行，这里写 999999）

target-simple.md:999999

观察项：VS Code 可能①把行号夹到文件末尾，②直接报错，③打开但不定位。三种都可接受，记下实际是哪种。

3. 行号不是数字（:abc，预期：改写真不动它）

target-simple.md:abc

正则只认 :数字 结尾，所以整串会被当成文件名 target-simple.md:abc（不存在）。 预期：报"文件找不到"之类。这算符合设计，只是不友好。

4. 文件名以数字结尾（测惰性正则会不会切错）

solid-320x240.gif（无行号）

文件名里含 320x240。预期：整个路径被当作文件、不会把 240 当成行号切掉。 若报错找不到文件 → 正则贪婪/惰性写错了（这是个经典的切分陷阱）。

5. fragment 形式（#L10，预期：按行号打开）

target-simple.md#L10

GitHub 风格的 #L10 现在也会被识别成行号（与 :10 等价）， fragment 不会被编码进文件路径。普通 fragment（如 #section）会被丢弃，只打开文件。

6. 直接写 command: 链接（验证 enableCommandUris）

command:vscode.open 打开 target-simple.md

这条不是改写出来的，是手写的 command: URI。 预期：能在当前窗口打开文件。这就是 enableCommandUris: true 存在的意义—— 没有这个开关，所有 command: 一律被宿主拒绝。

7. 非 file 的 vscode 链接（预期：走系统协议）

vscode://settings/wispkit.toc.depth

不是 vscode://file/ 形式 → 不改写。但 vscode 在宿主白名单里，预计能被受理（可能弹窗/另起窗口）。

8. 自定义 scheme（预期：被拒）

wispkit-demo://open?file=…

既不在白名单、也不是 command: → 预期点不动（控制台可能有拒绝日志）。 这条用来确认"白名单确实在起作用"。

9. 纯锚点（预期：页内跳转，正常）

跳到本行自身（#edge-anchor）

锚点不该被误判成文件链接。预期：页面滚动到本段（无变化也算正常，它就在眼前）。

10. 大小写与反斜杠

小写盘符 d:/ 路径

反斜杠路径 D:\…

改写逻辑会把 \ 统一成 /。 预期：反斜杠那条能工作（Windows 上人工写链接常这么写）；小写盘符那条也应变通（Windows 不区分大小写）。

全部试完后，把与预期不符的编号告诉我（例如"2 是直接报错、5 能另起窗口但很慢"），我按实际表现决定要不要改。
