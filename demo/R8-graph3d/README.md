## 前置

1. 安装 Wispkit 并重载窗口（`code --install-extension .\wispkit-0.1.0.vsix --force`，再执行 *Developer: Reload Window*）；
2. **用「打开文件夹」打开 `demo`**，不要只单独打开某个 `.md`；
3. 机器能创建 WebGL 上下文（3D 面板没有 2D 降级）。

## 怎么打开

- **入口 1（推荐）**：资源管理器里右键 `01-graphs.md` / `02-merge-scenario.md` / `03-codebase-trees.md` / `04-standalone.mmd` / `05-comments-and-edge-labels.md` → **3D 可视化浏览**。
- **入口 2**：先打开任意 Markdown 文件，命令面板执行 `Wispkit: 3D 可视化浏览`。
- 同一个文件重复打开只会 reveal 已经存在的面板，不会叠新标签。
- 命令面板在活动文件不是 Markdown / Mermaid 时会提示只支持 `.md` / `.markdown` / `.mmd` / `.mermaid`；没有活动文件时会提示先右键或打开一个 Markdown / Mermaid。
- **Mermaid 文件浏览**：双击 `04-standalone.mmd` 直接看渲染图；预览页工具栏的「3D 可视化浏览」与右键菜单等价。

## 界面速查

```
左图元素 [下拉]  右图元素 [下拉] │ 合并左右 重置视角 刷新 │ 布局 [下拉] 间隔 [滑杆] 1.00× [x]显示数据流名称  状态
```

| 控件 | 作用 |
|---|---|
| 左 / 右下拉 | 每项显示 `序号. 名称 · N 节点 / M 边`；「（不选）」可以留空一侧 |
| 合并左右 | 两侧都选中才可用；合并后按钮变「取消合并」，`Esc` 也能取消 |
| 重置视角 | 相机回到能看全整张图的方向与距离 |
| 刷新 | 重新读取并解析当前 Markdown，尽量保留左右选择 |
| 布局 | 自动（按拓扑）/ 紧凑分层 / **互斥 · 紧凑分层** / Louvain 壳内 FR-3D / 径向树 / 分层环 / 3D 力导向 / **互斥 · 3D 力导向**；切换后立即重绘 |
| 间隔 | 0.25×–3×；松开约 90 ms 后重新布局，相机会随包围半径缩放 |
| 显示数据流名称 | 默认勾选；勾选时边中点显示名称（与节点气泡同款文字），取消立即隐藏 |
| 分隔条 | 两侧都选中时出现；拖动夹在 15%–85%，双击复位 50% / 50% |

手势：**左键拖动旋转、右键拖动平移、滚轮缩放**；鼠标悬停在带注释节点的气泡区域会弹出注释 tooltip；触摸屏单指旋转、双指缩放 + 平移。

## 造「左右对比」

1. 打开 `02-merge-scenario.md` 的 3D 面板；
2. 左下拉选「登录流程 v1（左） · 流程图」，右下拉选「登录流程 v2（右） · 流程图」；
3. 两侧各占一半，拖动中间分隔条可以放大任意一侧；
4. 点「合并左右」→ 左右栏消失，只剩合并视图；按 `Esc` 回到分栏。

`01-graphs.md` 也可以任选两个图做对比（例如 ASCII 目录树 vs flowchart），但它们没有同名节点，合并后只是同场景并排。

## 造「同名节点合并」

`02-merge-scenario.md` 的登录流程 v1 / v2 是专门构造的：

- 三个同名节点：`登录页`、`鉴权服务`、`用户库`；
- 右侧独有节点：`风控服务`；
- 合并后应为 **4 节点 / 4 边 / 已合并 3 个同名节点**（`登录页 → 鉴权服务` 这条重复边被去重）。

「无同名节点 A / B」用于对照：合并后 **4 节点 / 2 边 / 0 个合并节点**，两侧仍保持独立。

### 代码结构双树（大规模同名合并）

`03-codebase-trees.md` 是规模更大的一组：

- 左选「树 A：底层库 · ASCII 树」（34 节点 / 33 边），右选「树 B：顶层模块 · ASCII 树」（66 节点 / 65 边）；
- 两棵树共享 23 个**不同名称**的末端节点，在树 B 中多处出现共命中 34 个节点；
- 合并后应为 **66 节点 / 98 边 / 已合并 34 个同名节点**；
- 共享叶子包括 `postMessage`、`three`、`OrbitControls`、`WebGL`、`markdown.api.render`、
  `XamlRender.exe`、`node:fs` / `node:path` / `node:child_process` / `node:crypto` / `node:os`、
  `workspace.fs` 与工具链名称 —— 它们就是「模块使用方」与「底层能力提供方」的接缝。

### 合并规则

- **只跨左右两个图元素合并**；同一张图内部的同名节点不合并。
- 名称比较：`trim` → 连续空白压成一个空格 → 去掉首尾引号 / 反引号 → 转小写；中文不受大小写影响。
- 右侧未匹配节点用 `r:` 前缀重新分配 id；右侧分组 id 同样重映射，避免与左侧撞车。
- 边按 `source + target + label + dashed` 去重，其余全部保留；因此两个图会通过共享节点连成一个整体。
- 没有同名节点时仍放进同一个 3D 场景，但两侧保持独立，统计会明确写「两侧没有同名节点」。

## void 悬空占位

Mermaid 导出器（例如 Drawcode 的模块交联）会给「对侧未创建 / 没有对端」的流建一个
标签为 `void` 的占位节点。3D 面板把它当作**悬空占位**：

- `void` 节点不画气泡，下拉与统计里的节点数也不含它；
- 与它相连的每条流变成从真实节点伸向空处的**悬空边**，边数照常统计，状态行追加「N 悬空」；
- 同一真实节点周围的多条悬空边会按角度散开，方向避开已有连线与附近气泡，长度取在常规边距附近；
- 箭头保持原来的 source → target 方向：`void → 节点` 指向真实节点，`节点 → void` 指向悬空端；
- ASCII 树里的 `void` 不处理；孤立或只与其它 `void` 相连的节点保留原样。

怎么验：打开 `06-void-dangling.md` 的 3D 面板，应看到 **2 节点 / 7 边 / 7 悬空**，
`void` 气泡消失，两条真实节点周围各有 3–4 条朝向不同的半截箭头。切换到任一种布局算法结果一致。

## 互斥布局（合并图专用）

「布局」下拉里的两个**互斥**算法是「紧凑分层」和「3D 力导向」的派生：

| 算法 | 基础布局 | 互斥效果 |
|---|---|---|
| 互斥 · 紧凑分层 | 紧凑分层 | 合并图中左右两侧各自的核心节点被推到布局左右两端 |
| 互斥 · 3D 力导向 | 3D 力导向 | 同上，基础位置由 3D 力导向决定 |

- **核心节点**：优先取本侧**独占节点**里入度为 0 / 可达节点最多的节点（根）；某一侧没有独占节点时，取该侧融合节点里的根。
- **两侧都有独占节点**：两组独占节点被推到两极，**同名合并出来的融合节点留在中间**，所以能一眼看出「两张图共享了哪些节点、各自独有什么」。
- **一侧是另一侧的子集**：融合节点留在原地，另一侧的独占节点被推到外侧；状态行会写「左核「…」· 右核「…」」。
- 单图（没有合并）或两侧完全相同时，互斥算法自动退回对应的基础布局，不会假装分离。

怎么验：打开 `02-merge-scenario.md`，左选 v1、右选 v2，合并后把「布局」切到「互斥 · 紧凑分层」，应看到公共链在左边、`风控服务` 被拉到最右；再切到「互斥 · 3D 力导向」，融合节点仍夹在左右核心之间。

### 自己造一个

1. 新建 Markdown，放两个 Mermaid 图或 ASCII 树；
2. 让它们共享至少一个**节点显示标签**（节点 id 不同没关系）；
3. 右键打开 3D → 左右各选一个 → 合并。

## 命名规则（下拉框里看到的名字）

优先级：Mermaid `title`（frontmatter 或 `title` 指令）> **最近的 Markdown 标题** > 图里第一个非空节点标签 > 文件名兜底；末尾追加图种。独立 `.mmd` / `.mermaid` 文件没有 Markdown 标题，按 `title` > 文件名命名。

- `01-graphs.md` 第 2 节带 frontmatter `title`，所以显示「构建流水线 · 流程图」；
- 同一个标题下有多张图时，后出现的会追加 `(2)`、`(3)`（见第 17 节）；
- 面板标题显示 `3D：文件名（N）`，N 是图元素数量。

## 已知边界（这些「没出现」是设计如此）

| 现象 | 原因 |
|---|---|
| 写在 ` ```js ` 等非 ASCII 围栏里的树不出现在下拉框 | 只会收集 `mermaid` 围栏与 `text` / `txt` / `plain` / `plaintext` / `ascii` / `tree` / `log` / `none` 等围栏里的树 |
| 只有一行连接线的「树」不出现 | 至少两行带标签连接线才认定为树 |
| 普通 Markdown 列表 / 表格 / 引用不会被当成树 | 正文裸树要求连接线，且排除 Markdown 结构行 |
| `requirementDiagram` 等未支持图种只有按行串成的链 | 使用通用兜底解析，语义（层级 / 流量 / 坐标）会丢失 |
| 每篇最多 200 个图元素、单图最多 600 个节点 | 超出部分截断；超大图性能未做真机压力测试 |
| 3D 与 Mermaid 主题样式不一致 | 3D 只解析拓扑，不移植 Mermaid 渲染器 |
| 禁用 WebGL 时面板显示错误层 | three.js 需要 WebGL 上下文，没有 2D 降级 |
